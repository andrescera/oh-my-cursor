=== Buffer-trim "race" determination: FALSE POSITIVE ===
event-logger.ts logEvent() runs:
    buffer.push(entry)
    if (buffer.length > MAX_BUFFER) buffer = buffer.slice(-TRIM_TO)
This is a single synchronous block. Bun's JS runtime is single-threaded and
runs to completion between event-loop turns; no other code can observe or mutate
`buffer` mid-slice. There is no await between the push and the trim, so no
async interleaving is possible. Therefore the reported "buffer-trim race" is NOT
a real hazard — no mutex/lock added (would be dead weight under single-thread).

Test "burst beyond MAX_BUFFER trims oldest and keeps newest" proves correctness:
pushing MAX_BUFFER+1 (10001) entries trims to TRIM_TO (5000), oldest idx dropped
(0..5000 gone), newest kept (oldest kept idx = 5001, newest kept idx = 10000).

=== REAL hazards fixed ===
(a) Pending events lost when process exits before the 500ms debounced flush
    fires. Fixed: gracefulShutdown now `await flushNow()`; process.on("beforeExit")
    backstop added. QA (task-7-flush-on-shutdown.txt) confirms 5/5 events land.
(b) Unawaited flush errors. Fixed: scheduled flush wraps flushPending() in
    try/catch+log; flushNow() logs+rethrows; flushPending() restores `pending`
    on write failure so entries are retried rather than dropped.
